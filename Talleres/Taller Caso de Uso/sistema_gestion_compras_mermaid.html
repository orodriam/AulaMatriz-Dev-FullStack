01 · Contexto

Descripción del sistema

El Sistema de Gestión de Compras permite a un usuario consultar productos, administrar un carrito y obtener el valor final de una compra. El cálculo contempla precios, cantidades y un descuento del 10 % cuando el usuario posee una membresía activa.

El administrador complementa el proceso mediante la gestión del catálogo y la consulta de ventas. El modelo separa las responsabilidades de interfaz, lógica de negocio y persistencia de datos.

UsuarioConsulta productos, administra el carrito y calcula el total de su compra.
AdministradorGestiona productos y consulta información de ventas.
Regla principalUna membresía activa genera un descuento del 10 % sobre el subtotal.

03 · Especificación

Caso de uso crítico: Calcular total de compra

CódigoCU-03
NombreCalcular total de compra
Actor principalUsuario
ObjetivoDeterminar el subtotal, descuento aplicable y total final de los productos agregados al carrito.
DisparadorEl usuario solicita visualizar o confirmar el total de su compra.
PrioridadAlta
PrecondicionesEl sistema se encuentra disponible; el usuario puede acceder al carrito; los productos poseen precio y cantidad válidos.
PostcondicionesEl sistema presenta subtotal, descuento y total final. No se modifica el catálogo durante el cálculo.

Flujo principal

  1. El usuario accede al carrito de compras.
  2. El frontend solicita al backend el cálculo del total.
  3. El backend valida que el carrito contenga productos.
  4. El backend consulta en la base de datos la información vigente de los productos.
  5. El sistema calcula el subtotal multiplicando el precio por la cantidad de cada producto.
  6. El backend consulta el estado de membresía del usuario.
  7. Si la membresía está activa, el sistema calcula un descuento equivalente al 10 % del subtotal.
  8. El sistema calcula el total final mediante total = subtotal - descuento.
  9. El backend devuelve subtotal, descuento y total al frontend.
  10. El frontend presenta el resumen final al usuario.

Flujos alternativos

A1 · Carrito vacío. Si el carrito no contiene productos, el sistema no ejecuta el cálculo y presenta subtotal, descuento y total en cero.
A2 · Usuario sin membresía activa. El sistema establece el descuento en cero y calcula el total con el valor completo del subtotal.
A3 · Producto inexistente o no disponible. El backend informa la novedad al frontend y evita confirmar un total basado en información inválida.
A4 · Error de acceso a datos. Si no es posible consultar la base de datos, el sistema informa que el cálculo no pudo completarse y no presenta un total como definitivo.

Reglas de negocio

RN-01. El subtotal corresponde a la suma de precio × cantidad de todos los productos válidos del carrito.
RN-02. Una membresía activa otorga un descuento del 10 % sobre el subtotal.
RN-03. Si no existe membresía activa, el descuento es igual a cero.
RN-04. Un carrito vacío produce subtotal, descuento y total iguales a cero.

Diagrama de secuencia

        B-->>F: Retornar subtotal, descuento y total

06 · Cierre

Conclusión

El modelado permite observar el mismo proceso desde tres perspectivas complementarias: los casos de uso describen qué funciones ofrece el sistema y quién las utiliza; la especificación formaliza las condiciones y reglas del proceso; y el diagrama de secuencia explica cómo colaboran frontend, backend y base de datos para producir el resultado.

La separación de responsabilidades facilita que la solución pueda evolucionar hacia una aplicación real sin mezclar la presentación, la lógica de negocio y el almacenamiento de información.
